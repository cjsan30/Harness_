## 초기 감사에서 발견한 문제

- 설치된 Git hook 경로가 `/mnt/c/...`인 상태에서는 Windows preflight가 실패했습니다. 이는 특정 원본 환경의 설정 문제이며 현재 개발 저장소에는 hooksPath 설정이 없습니다.
- 당시 게시판 E2E의 `spawnSync npx.cmd EINVAL` 및 예제 데이터 기반 검증 한계를 확인했습니다. 해당 제품 코드는 이후 제거했습니다.
- `generate_env_manifest.ps1`, `start_from_intake.ps1`에서 Secrets And Access의 값이 생성 문서로 복사되는 것을 가짜 credential로 재현했습니다.
- 승인 ID 직접 지정 경로에서 현재 branch/head와 승인 범위를 연결하지 않아 다른 변경의 승인을 사용할 가능성이 있었습니다.
- standalone root 감지는 부분적이고 많은 경로가 `<target>/harness`를 가정했습니다.
- invocation 7,200초, dispatch/cycle 1,800초 등 나이 기반 잠금 만료는 실제 소유자 생존을 확인하지 않았습니다. 초기에는 코드상 위험 분석이었고 첫 구현의 회귀 테스트로 재현·수정했습니다.
- CI·보안·릴리스 생성물 감사 일부가 문자열 존재 검사이므로 실제 실행 성공으로 보고하면 안 됩니다.

앞의 승인/intake/잠금 문제는 첫 구현에서 핵심 경로를 수정했습니다. 당시에는 경로 통일, 실제 실행 증거, 고아 프로세스와 crash 복구가 남아 있었습니다. 이후 구현 상태는 후속 기록과 세션 인계를 확인합니다.

## 비용 비교: 공통 가정

이하 수치는 이전 대화에서 제시한 **2026-10-14 당시 견적용 가정**을 보존한 것입니다. 이번 문서화에서 가격을 다시 조회하지 않았습니다. 실제 구매·예산 결정 시 공식 가격·모델 존재·제공 조건을 다시 확인해야 합니다. 작업량과 캐시율은 이 Harness의 측정값이 아닙니다.

- Harness가 충분히 안정화됐다고 가정했습니다. 현재 완성도에 대한 평가와 별도입니다.
- 환율은 `$1 = 1,400원`, 세금 제외로 고정했습니다.
- AI 개발 API 비용은 개발자가 코드 작성·수정·검증을 시키는 비용입니다. 개발자 인건비, 고객 챗봇 운영 API, 호스팅과 외부 서비스는 별도입니다.
- “작업 1개”는 독립적으로 구현·검증 가능한 변경 단위입니다. 프롬프트 1개나 실제 Harness assignment와 자동으로 동일하지 않습니다.
- 작업 1개당 누적 입력 100만 토큰 + 청구 출력 5만 토큰(추론 포함), 검토·재시도 여유 50%를 가정했습니다.
- 낮은 비용 쪽은 입력 normal 20% / cache write 10% / cache hit 70%, 높은 쪽은 캐시 없음입니다. 범위는 통계적 신뢰구간이나 비용 상한이 아닙니다.
- 같은 토큰 수와 단가로 계산했을 뿐, Codex와 Claude의 실제 문제 해결량·속도·재시도 횟수가 같다고 검증하지 않았습니다.

사용자가 명확히 고른 비교 기준은 **Codex Pro $100/월**입니다. 실제 가입 상태나 남은 한도는 조회하지 않았습니다. 리셋을 사용한 적도 없습니다.

“리셋 1회”는 한도를 모두 사용한 뒤 한 번 초기화해 총 두 번의 한도를 쓴다는 가정으로 설명했습니다. 이 해석은 사용자가 별도로 명시적으로 확정한 내용은 아닙니다. 월 구독 전체가 정확히 두 개의 사용 구간이라는 뜻도 아닙니다. 당시 Pro의 5시간 제한 없음/주간 한도 가능성을 기준으로 논의했으며 다음 세션에서 현행 정책을 확인해야 합니다.

이미 보유한 리셋을 한 번 쓰고 추가 결제를 하지 않는다면 기본료 약 14만원이라는 가정입니다. API 달러 단가로 구독의 구현량을 환산할 수 없고, 챗봇 MVP 완성을 약속할 수는 없습니다.

| 완료·검증한 작업 1개당 실제 한도 소모가 다음과 같다면 | 총 200%에서 가능한 산술적 작업 수 |
| --- | ---: |
| 1% | 200 |
| 2% | 100 |
| 4% | 50 |
| 5% | 40 |

위 수치는 관측값이 아닙니다. 먼저 대표 작업 10개를 구현·검증하고 한도 변화를 측정하자는 제안이었습니다. 10개에 20%를 썼다면 두 번의 한도에서 약 100개가 된다는 조건부 계산입니다. 60~120개 RAG 범위와 비교할 수 있지만 검토·회귀·한도 변동을 포함한 새 실측이 필요합니다. 첫 목표는 FAQ와 기본 문서검색 MVP로 잡고 검증 몫을 남기는 방향을 논의했습니다.
